# V5.3 — Smart sentence context

## Problem reproduced from the reader screenshots
Tapping different words in the same printed French sentence could return different visual-line fragments, e.g.:

- `remporté` -> `Nicolas a`
- `d’éloquence` -> a middle fragment
- `condisciples` -> another middle fragment

The cause was EPUB DOM structure, not French punctuation: V5.2 accepted the nearest `div` as a sentence container. Some EPUBs use one `div` per visual line, so sentence extraction stopped at layout boundaries.

## Fix
- `div` is no longer treated as a trusted sentence boundary.
- Prefer true semantic blocks (`p`, `li`, headings, table cells, etc.).
- When a semantic block is unavailable, flatten the chapter body while preserving spaces (not line breaks) between DOM blocks, so visual-line DIVs cannot become fake sentence boundaries.
- Map the exact tapped text-node offset into that flattened chapter text.
- Use French `Intl.Segmenter` around that exact offset, with the abbreviation-aware fallback retained.
- Increase the long-sentence safety window from 520 to 1000 characters so valid literary sentences are not cut prematurely.

## Expected result for the reported passage
Tapping `remporté`, `d’éloquence`, or `condisciples` should all resolve to the same sentence:

`Nicolas a remporté le prix d’éloquence, qui récompense chez lui la quantité, sinon la qualité, et il a quitté ses condisciples qui ont nom : Alceste, Rufus, Eudes, Geoffroy, Maixent, Joachim, Clotaire et Agnan.`
